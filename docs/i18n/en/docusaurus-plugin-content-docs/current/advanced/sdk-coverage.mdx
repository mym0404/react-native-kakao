# Native SDK coverage

The Core, User, Social, Channel, Share, Navi, and Cert packages expose the public service APIs of the Kakao Android and iOS SDKs. Web uses the JavaScript SDK and REST APIs available to user access tokens. Browser limitations for app switching, local keys and sessions, and SDK URL builders are listed below.

Implementation coverage and verified success responses are separate. Success paths that require an approved app or an installed Kakao app are listed under [Verification coverage](#verification-coverage).

## SDK versions and audit scope

Native defaults come from [`sdkVersions` in `packages/core/package.json`](https://github.com/mym0404/react-native-kakao/blob/404c4a856abe63fc159df3701f63a5f1cec10f7a/packages/core/package.json). Overrides can change the behavior described here. Use [`getKakaoSDKInfo()`](/docs/core/initialize-sdk) to inspect the running version.

| SDK                                 | Version                                                                  | Scope                                                                |
| ----------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| Android                             | `2.25.1`                                                                 | Common, Auth, User, Talk, Friend, Share, Template, Navi, Cert        |
| iOS                                 | `2.29.0`                                                                 | Public SDK products for the same services                            |
| Partnership friend picker           | Android `1.0.0`, iOS revision `83917aaf996e5d4072e73b681507228fbd967d42` | Partnership friend selection options                                 |
| JavaScript verification environment | `2.8.4`                                                                  | The app installs its SDK script using [Web setup](/docs/install-web) |

The audit covers public service methods, input options, and response fields in these SDKs. Internal methods, retired APIs, and callback/async overloads of the same operation are not duplicated as separate JS APIs. SDK client replacement and token-store replacement are not exposed. Push, Talk Calendar, administrator REST APIs, and the separate Kakao Maps SDK are outside this native SDK comparison. See Kakao's [official support matrix](https://developers.kakao.com/docs/en/getting-started/scope-of-support) for the wider API catalog.

## Public APIs by feature

Unless a platform is specified, the features below are implemented on both Android and iOS. The Web column describes browser behavior.

Certification requires Kakao approval and server transactions. `authorizeForCertWeb` is web only; completing its redirect request does not complete authentication or signing. Calling it on native rejects with `Package-UnsupportedPlatform`.

## Response contracts

Timestamps use Unix seconds; validity durations use seconds. SDK keys and enums are mapped to the public TypeScript types. `null` or absent fields caused by missing consent or app permissions are not filled with invented success data.

Sharing, messaging, logout, and property mutations without a success value complete as `Promise<void>`. Friend sends return successful UUIDs by default, or `{ successfulReceiverUuids, failureInfos }` with detailed results enabled. Message receipt, completed app switching, and authentication after a web redirect require separate checks in each flow.

Asynchronous data queries and mutations propagate SDK/HTTP failures as Promise rejections. Status and launch functions such as `isLogined`, `navigateTo`, and `shareTo` can return `false` for token-query or SDK-launch failures. JavaScript input validation can throw synchronously before returning a Promise. Follow each API's guide for its return type and error handling.

## Verification coverage

This is the verification status as of October 21, 2026. Builds and input/response checks do not verify success paths when app permissions or installation prerequisites are missing. Each PR's `Confidence level` describes the scope verified for that change.

Earlier authenticated checks also used Android `2.25.0` and JavaScript `2.7.1`. The [SDK update](https://github.com/mym0404/react-native-kakao/pull/174) and subsequent PRs record the checks performed after version updates. Not every authenticated success flow below was rerun with Android `2.25.1` and JavaScript `2.8.4`.

| Feature                              | Verified                                                                                                                                           | Remaining success paths or conditions                                                                                                                    |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Module integration                   | Android/iOS Release builds and 8/8 smoke tests per platform. Channel, Social, and Share also build with only Core + the selected module installed. | Feature approval and authentication are separate prerequisites.                                                                                          |
| SDK initialization and information   | Native settings, Android identifier KA header application/restoration and iOS ignoring it, actual web SDK version and initialized state | Authentication callback with a registered custom multi-app scheme                                                                                        |
| Login selector and refresh           | Android selector login and token refresh; signed-out errors and cancellation on both platforms                                                     | Successful iOS selector login/refresh, installed-KakaoTalk switching and callbacks                                                                       |
| Android login request code           | Signed 32-bit integer bounds, out-of-range rejection, account-login fallback, and cancellation | Forwarding with KakaoTalk installed. The pinned SDK uses this value only in diagnostic logs. |
| Explicit-token refresh               | Actual Android/iOS `InvalidGrant`, web unsupported error, unchanged empty storage after failure, 41 input checks, and 20 iOS SDK refresh/response checks | Live refresh and storage with a valid external token                                                                                                    |
| iOS refresh request logging          | Debug app: `true` logs the request and response body; `false` hides both. Both return `InvalidGrant`, and global SDK logging remains `false` | The SDK still logs a `response: -` placeholder. |
