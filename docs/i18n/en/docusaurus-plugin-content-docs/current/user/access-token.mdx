# Managing Tokens

## Exchange an authorization code

`issueAccessTokenWithCode()` exchanges an existing authorization code for a `KakaoLoginToken` on iOS and web. Use it when handling a code obtained through a separate authorization flow. On iOS, [`login()`](./login.mdx) performs the exchange. On web, `login()` redirects to authorization; exchange the code returned by that redirect separately.

```tsx
import { issueAccessTokenWithCode } from '@react-native-kakao/user';

const token = await issueAccessTokenWithCode({
  code: authorizationCode,
  codeVerifier,
  redirectUri,
});
```

`codeVerifier` is the verification value created for a PKCE (Proof Key for Code Exchange) authorization request. Pass the same value if that request used PKCE. `redirectUri` must also match the authorization request. On iOS, omitting it uses the initialized SDK's default redirect URI. Web requires it.

The iOS SDK stores the issued tokens. Web uses the REST API key supplied during Core initialization, then stores the access token in the JavaScript SDK and the library's web storage. The refresh token is returned but not stored. Pass `web: { clientSecret }` if your web app requires a client secret. Expiry timestamps use Unix seconds, lifetimes use seconds, and `scopes` contains scope IDs.

The public Android SDK does not provide a separate code-exchange API, so Android rejects with `Package-UnsupportedPlatform`. Use `login()` or `loginWithKakao()` there. The existing `issueAccessTokenWithCodeWeb()` remains web only and returns its existing REST response shape without storing tokens.

## Check Stored Token Presence

`hasToken()` returns `Promise<boolean>` on Android, iOS, and web. It reads the current platform SDK's local token storage without calling Kakao's token information API or refreshing a token. This lets an app check for stored credentials during startup or while offline.

```tsx
import { hasToken, isLogined } from '@react-native-kakao/user';

const hasStoredToken = await hasToken();
if (hasStoredToken) {
  const isTokenValid = await isLogined();
}
```

`true` means the SDK has a stored token. That token may have expired or been revoked. Use `isLogined()` to validate it with Kakao before treating the user as authenticated.

The method returns only a boolean and does not expose the stored token.

## Query token information

`getAccessToken()` validates the access token with Kakao and returns the user ID, app ID, and remaining lifetime in seconds. It does not return the access token string.

It is defined as follows.

```tsx
export function getAccessToken(): Promise<KakaoAccessTokenInfo>;
```

The type is as follows.

```tsx
export interface KakaoAccessTokenInfo {
  id?: number;
  appId: number;
  expiresIn: number;
}
```

### Example

```tsx
getAccessToken();
```

## Refresh stored tokens

`refreshToken()` uses the refresh token stored by the Android or iOS SDK to refresh the access token. The SDK stores the updated tokens and returns the same [`KakaoLoginToken` as `login()`](./login.mdx#response). Expiry timestamps use Unix seconds; remaining lifetimes use seconds.

```tsx
import { refreshToken } from '@react-native-kakao/user';

const token = await refreshToken();
```

If no refresh token is stored or it has expired, the method rejects with the Kakao SDK error. Call `login()` again. The JavaScript SDK does not expose token refresh, so web rejects with `Package-UnsupportedPlatform`.

For web token exchange and storage, follow [Web login](./login-web.mdx).
